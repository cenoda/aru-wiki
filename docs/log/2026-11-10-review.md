## 2. 운영 방침

### 2.1 진행도 체크: 만들지 않는다 (결정)

- 설계는 브라우저 저장(localStorage)이라 로그인과 서버는 필요 없다. 그래도 기기 사이에 공유되지 않고, 브라우저 데이터를 지우면 사라져 사용자가 기대하는 "내 진행도"가 되지 못한다.
- 스포일러 차단은 버전 선택("7.2까지 공개")이 이미 맡는다.
- Gscouter도 같은 이유로 만들지 않았다.

### 2.2 오류 신고: 인라인 익명 신고 + OCI 초경량 수집기 (방안 A 결정, 구현 완료)

- 사용자 제기:
  - GitHub 이슈는 일반 방문자에게 맞지 않는다.
  - 위키백과식 운영이 낫지 않나?
  - 카드마다 둘 만큼 정확도가 낮은가?
  - `mailto:contact@aru.wiki`는 제보자(상대방)의 이메일 주소가 노출되어 마음에 들지 않는다.
- 위키백과식 공개 편집은 계정, 편집 이력, 되돌리기, 반달 대응, 서버 DB가 필요하다. design.md의 "보류: 계정, 서버 DB"와 맞지 않는다. 자동 생성 문장은 인용과 출처(리비전)에 묶여 있어서 직접 고치면 그 연결이 끊기는 문제도 있다.
- **결정(방안 A):**
  - 우측 상세 패널 하단에 이메일·계정 입력란이 없는 인라인 익명 오류 제보 창구(`src/ReportBox.tsx`, 유형 칩 + 선택적 200자 메모)를 둔다.
  - 백엔드는 Caddy 뒷단 `/api/report`에 연결되는 무의존성 초경량 수집 데몬(`scripts/report-server.mjs`)이 받아 `data/reports.jsonl`에 기록한다(IP 원문은 디스크에 저장하지 않고 일일 솔트 해시로만 도배 제한 후 폐기, 선택적 웹훅 알림 지원).
  - 권장 연결선 20~30개를 표본으로 사람이 읽어 오류율을 잰다(design.md 5절 5번).

### 2.3 배포: OCI 인스턴스 (결정)

필요할 때 사용자에게 인스턴스를 요청한다. 사이트는 `npm run build` 결과물(정적 파일)뿐이라 무료 등급 ARM 인스턴스로 충분하다. 사용자에게 받을 것:

- SSH 접속 정보
- 80·443 포트 개방 (OCI Security List와 인스턴스 방화벽 둘 다)
- aru.wiki DNS A 레코드를 인스턴스 IP로

웹 서버는 Caddy를 제안한다(인증서 자동 갱신).

## 3. UI 개선

### 3.1 카드 끌기: 막는다 (A안 결정)

- 지금은 React Flow 기본값 때문에 카드를 끌 수 있다. 관성, 가속, 복원력이 없어 모양이 그대로 꼬인다. 사용자 평: "아예 안 움직이는 게 나을 수준".
- **결정(A안):** `<ReactFlow nodesDraggable={false}>`로 카드 끌기를 막는다.
  - 지도는 ELK가 정한 배치를 보여 주는 화면이라 물리 시뮬레이션과 맞지 않는다.
  - 막으면 `RouteEdge`의 "끌어서 어긋나면 smoothstep으로 대체" 분기는 지워도 된다(`src/FocusView.tsx`).

### 3.2 화면 이동 범위에 복원력 (A안 결정)

- 지금은 화면 중심을 거의 끝없이 바깥으로 옮길 수 있다.
- 검토한 안:
  - **A안 (탄성 복원, 결정):** 이동이 끝날 때(`onMoveEnd`) 범위 밖이면 애니메이션으로 되돌린다(드래그 중 저항감 또는 복귀 애니메이션 적용).
  - B안 (딱딱한 벽): React Flow `translateExtent`에 그래프 범위와 여백을 준다.
- 아틀라스와 갈래 보기는 범위가 다르니 각각 계산한다.

### 3.3 빈 공간

- 원인: 아틀라스가 지하철 노선도 배치(시대별 줄, 버전별 열, 같은 이야기는 한 높이)라서 다음 부분이 길게 빈다. 짧은 노선의 오른쪽, 막이 적은 버전 열, 시대 사이 간격(`ERA_GAP` 90)이다.
- 검토한 방향:
  - (가) 버전 열 폭을 내용에 맞추고, 짧은 노선끼리 한 줄에 더 채운다.
  - (나) 빈 곳에 그 버전의 지역·주요 사건 같은 정보를 놓는다.
  - (다) 지역 단위로 묶어 배치를 새로 짠다.
- **사용자 선택: (나), 그리고 임무 카드에 이미지를 넣는다** (3.4).
- **데이터 재료 확보 완료 (`versions.json`):** 로컬 `.cache/fandom/`의 `Version/X.Y` 문서 54개에서 한국어 버전명(`title_ko` 54/54)과 신규 개방 지역 목록(`areas`, 30개 버전 총 110개 지역·하위 구역, `ko-names.json` 연동 한국어 공식 명칭 100% 매칭)을 `scripts/fandom/build-stage1.mjs`로 파싱해 반영했다.

### 3.4 임무 이미지 및 인물 매칭 (이미지 정책은 2026-11-11 결정으로 대체, 데이터 파싱 완료)

임무 카드나 빈 공간에 대표 이미지·상징을 둔다.

- 전설 임무: 그 전설 임무의 주인공 캐릭터
- 마신 임무 중간장·여정 장: 데인슬레이프·신학·방랑자처럼 그 장의 중심 인물
- 정규 마신 임무·월드 임무 등: 지역/테마 자체 제작 SVG 문장 + 핵심 등장인물/동반자 매칭

**저작권과 출처 (2026-11-11 정정).**

이 절에 먼저 기록했던 ‘B+C 결합 결정’과 ‘원칙 1 명확화’는 당시 승인되지 않은 내용이었다. 현재 방침은 [2026-11-11 이미지 방침의 B안](../image-policy.md)으로 대체한다. 과거 B+C는 출처 조합 명칭이고, 현재 B안은 출시된 식별용 이미지를 추출본이라는 이유만으로 배제하지 않는 정책이다.

- 이는 이미지에 대한 정책 예외이며, HoYoverse의 명시적 허용이 확인됐다는 뜻은 아니다. 근거와 미확인 범위는 [권리·운영 위험 검토](../rights-risk.md)를 따른다.
- 유출 자료 사용·게시와 ToS 위반 행위를 금지하고, 공개 여부·출처·제3자 권리를 확인한다. 게임 이미지는 프로젝트 CC BY-SA 적용 대상에서 제외한다.
- 지역·테마 자체 제작 SVG는 보조 요소이며, 인물 초상 확보를 일부 캐릭터에만 한정하지 않는다.
- 모든 권리 문의는 [contact@aru.wiki](mailto:contact@aru.wiki)에서 수신 후 72시간 이내 답변하며, HoYoverse의 수정·삭제 요청은 즉시 따른다.

**임무와 인물 짝짓기 (로컬 캐시 파싱 보강 완료):**
- `scripts/fandom/build-stage1.mjs`와 `scripts/fandom/build-units.mjs`를 보강해 로컬 `.cache/fandom/`의 `{{Act Infobox}}`·`{{Quest Infobox}}`에서 `character`, `chapter`, `actNum`, `group` 필드를 `data/generated/quests.json`과 `data/generated/quest-units.json`에 파싱·반영했다:
  - **전설 임무 막(`ACT:STORY` 83개):** 인포박스 `character` 필드로 **83/83개(100%)** 주인공 캐릭터가 오차 없이 매칭되며, `group` 필드로 일반 전설 임무(58)·초대 이벤트(`Hangout Event`, 19)·부족 견문(`Tribal Chronicles`, 6)이 구분된다.
  - **마신 임무 막(`ACT:ARCHON` 52개):** 인포박스 `chapter`(52/52)와 `character`(여정 장 5개 `Traveler`)로 여정 장(데인슬레이프 등)·중간장(`Interlude Chapter` 4개)·정규 장(43개)이 구분되며, 하위 임무 등장인물(`quest-characters.json`) 및 전역 빈도 결합으로 중심 인물을 자동 추출할 수 있다.
  - **월드 임무 막(`ACT:WORLD` 50개):** `마녀의 과제`(`Witch's Homework`) 12개 막은 인포박스 `character` 필드가 명시되어 있으며, 나머지 장편 시리즈는 `chapter`와 `quest-characters.json` 최다 등장 동반자(아라마, 안, 어린 산룡 등)로 매칭된다.
  - **한국어 명칭 보강:** `build-stage1.mjs`에 `ko-names.mjs` 폴백을 연결해 `quests.json`의 한국어 명칭 누락(`missingKo`)을 68건에서 3건(2,472개 중 99.9% 완비)으로 줄였다.
- **스포일러:**
  - 인물의 얼굴이나 정체가 곧 스포일러인 경우가 있다. 이미지도 버전 선택기를 따른다.
  - 정체가 늦게 드러나는 인물(`character-aliases.json` 등)은 공개 버전 이후에만 보인다.
